# 지형 타일 이음선 제거

Blender에서 구운 지형 타일을 OVERDARE에 깔면 **타일 경계가 선으로 보인다.** 화성(장안문)과
산옥(JSN_Sangok2) 두 맵에서 실제로 없앨 때까지 돌린 기록이다. 결론부터:

> 파일을 아무리 연속으로 만들어도 **곧은 경계는 선으로 읽힌다.** Studio가 메시마다 하늘광을
> 조금씩 다르게 주기 때문이다(경계에서 ~12 % 밝기 차, Blender 렌더에는 없음). 파일 쪽에서
> 고칠 수 있는 건 "선이 생길 여지"를 없애는 것뿐이고, 마지막 한 끗은 **지면 기복**과
> **색 마스크 연속성**이 가른다.

## 통한 조합

1. **모든 지형 메시를 한 격자의 ≤ 50 m 타일로.** 크기가 다른 메시(예: 40 m 지형 타일 옆
   130 × 50 m 산벽 슬래브)가 맞붙는 자리가 가장 잘 보인다.
2. **텍스처는 1024.** 2048로 올리면 Studio가 ~1024로 줄여 써서 **오히려 흐려진다**
   (화성 TER5: 파일은 4.8 cm/px인데 화면은 ~10 cm/px로 보였다).
3. **타일 바운드를 동일하게.** 땅속에 1 mm 삼각형 두 개를 묻어 모든 타일을 같은
   `W × H × D`로 맞춘다. 평평한 마당 타일만 높이 1 cm, 언덕 타일은 1.1 m 식으로 제각각이면
   메시별 하늘광 계산 해상도가 달라진다.
4. **월드 연속 베이크.** 타일 밖 `PAD` 텍셀만큼 **실제 이웃 땅을 확장해서** 굽는다.
   베이크 마진의 EXTEND는 가장자리 텍셀을 늘려 바를 뿐이라 이웃의 땅이 아니다.
5. **해석 노멀.** 각 타일의 면으로 노멀을 재계산하면 경계 정점이 이웃 절반을 못 봐서 음영이
   꺾인다. 높이함수의 기울기(`-dh/dx, -dh/dy, 1`)로 직접 넣으면 두 타일이 비트 단위로 같다.
6. **평평한 구역에 ±15 cm 기복.** 이게 마지막 한 끗이었다. 평평하면 타일 전체가 한 톤이라
   메시별 밝기 차가 그대로 선이 된다. 기복이 있는 바깥 지형에는 처음부터 선이 없었다.
   도로·광장·가장자리는 0으로 페이드하고, 벽 옆은 **올라가기만** 하게 해서 밑동 틈을 막는다.
7. **색 마스크도 경계를 넘어 연속이어야 한다.** 산옥은 1~6을 다 해도 선이 남았는데, 원인은
   메시가 아니라 색이었다: 낙엽 채널이 플레이 rect 가장자리에서 **1 m 안에 0.55 → 0** 으로
   끊겼다(forest/strip 마스크가 rect 안에서만 정의됨). 가장자리 ±8 m에서 마스크를 흐려
   해결했다.
8. **모자라면 모델로 덮는다.** 경계선을 따라 소형 식물을 뿌린다. 단, 경계 바로 위에 좁게
   몰면 "심어 놓은 줄"이 되어 더 눈에 띈다 — σ 2.5 m 이상으로 넓게 흩고, 경기구역 안에만.

## 안 통한 것들 (다시 하지 말 것)

| 시도 | 결과 |
|---|---|
| UV 패딩 8 → 24 px, 베이크 마진 48 EXTEND | 가장자리 ~8 % 밝은 띠는 사라졌지만 선은 그대로 |
| 경계를 노이즈로 뒤엉키게(지그재그 소유권) | 선이 **울퉁불퉁해질 뿐** 그대로 — 메시 단위 밝기 차라는 증거가 됐다 |
| 타일을 4장으로 크게 + 2048 텍스처 | 선은 줄었지만 잔디가 두 배 흐려져 철회 |
| 타일을 겹쳐 깔기 | 검토만. 위 타일이 끝나는 자리에 선이 그대로 옮겨갈 뿐이고, 같은 높이면 z-파이팅 |

## 함정

- **`UnitExtent`를 같이 안 바꾸면 지형이 날아간다.** Studio는 `Size / UnitExtent`로 스케일한다.
  `.ovdrjm`을 직접 고쳐 `MeshId`만 바꾸면 옛 값이 남는다 — 평평했던 타일의 `UnitExtent.Y 0.0005`가
  남아 새 지형이 세로로 **~50만 배** 늘어났다. 항상 `UnitExtent = (X/2, Y/2, −Z/2)`.
- **GUI 임포트가 레벨에 복제본을 남긴다.** 임포트 후 `Workspace` 바로 아래에 임포트 이름 그대로
  `Model`이 한 벌 깔려 있을 수 있다(월드 원점 근처). 교체 스크립트는 컨테이너 안만 보므로 그대로
  남아 인스턴스 수만 늘린다 — fps 레버가 인스턴스 개수라 바로 손해다. 교체 후 찾아서 지울 것.
- **충돌 슬랩 윗면은 지면 아래로.** 튀어나오면 격자선처럼 보인다(두께 40, 윗면 −30 cm).
  기복을 ±15 cm·평균 0으로 잡으면 기존 슬랩을 다시 만들 필요가 없다.
- **경계벽 밖 슬랩·소품은 지워도 된다.** 도달 불가인데 인스턴스 예산만 먹는다.

## 진단 순서

1. **경계를 가로질러 값을 찍어 본다** — 1 m 간격으로 높이와 색 마스크 4채널. 색이 튀면 7번,
   높이만 튀면 지형 함수. 메시부터 고치기 전에 이걸 먼저 한다(산옥에서 메시를 두 번 갈아엎고
   나서야 색이 원인이란 걸 알았다).
2. **텍스처끼리 직접 비교한다.** 경계 양쪽 타일의 경계선 텍셀 열을 뽑아 평균 색차를 본다
   (`rebake_tiles3.seam_check`). 넓은 띠로 평균 내면 국소 불연속이 묻힌다.
3. **눈높이 스크린샷.** 편집기에서 경계 바로 위에 서서 본다. 단, 경기구역 경계벽처럼 편집기
   전용 반투명 판이 그 자리에 있으면 판단이 안 되니 플레이로 확인한다.

## 파일

```
blender/terrain_seams/hwaseong/
  rebake_tiles3.py    월드 연속 PAD 베이크 + 해석 노멀 (4·5·6이 전부 이걸 재사용)
  rebake_tiles4.py    (실패) 노이즈로 뒤엉킨 경계
  rebake_tiles5.py    (실패) 큰 타일 4장 + 2048. 동일 바운드·낙엽·얼룩 코드는 6이 재사용
  terrain6.py         ±15 cm 기복 필드 (도로·가장자리 페이드, 벽 옆은 상승만)
  rebake_tiles6.py    안쪽 20장 최종본 + 소품 Y 보정값 산출
  rebake_outer6.py    외곽 10장 (구멍 뚫린 링, 1 m 격자)
  patch6.py           .ovdrjm 교체: 메시·텍스처·위치·크기·UnitExtent + 소품 재안착
  patch_out6.py       외곽 링 교체
  swap3/4/5.py        임포트된 에셋 ID 해석 → 교체 계획 JSON
  grass2000.py        경계선 중심 소형 식물 2,000개 산포
blender/terrain_seams/sangok/
  sgk6_tiles.py       지형 12장 + 산벽 6장 → 한 격자 30장 재절단, SGK_PREFIX로 라운드 구분
  sgk6_patch.py       옛 18장 삭제 + 새 30장 삽입 (기존 인스턴스 복제 → 속성 승계)
  sgk7_patch.py       같은 지오메트리일 때 메시·텍스처 ID만 교체
```

경로 상수는 작성 당시 작업 루트를 가정한다. 다른 맵에 쓸 때는 높이함수·색 마스크·컨테이너
이름만 갈아끼우면 된다.

## 대량 교체는 `.ovdrjm` 직접 수정이 싸다

인스턴스 2,000개를 `create_instances`로 넣으면 호출마다 guid 목록이 통째로 돌아와 토큰을
먹는다. 같은 메시를 쓰는 **기존 인스턴스를 복제**해 새 guid·`ObjectKey`만 바꿔 JSON에 끼워
넣고 `apply` 한 번이면 끝난다. 쓰기 전후로 `json.loads`로 검증하고 guid 유일성을 확인할 것.
백업은 매 단계 `.bak_*`로 남긴다.
