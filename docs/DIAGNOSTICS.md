# 진단 기법 — 규약이 의심스러울 때 뭘 해보는가

이 리포의 규칙 대부분은 아래 방법으로 잡아냈다.
**값을 다시 읽어 대조하는 건 검증이 아니다** — 내가 쓴 값을 내가 읽는 것일 뿐이다.
그림으로 보거나, 독립적인 경로로 측정해야 검증이다.

---

## 1. 짐벌락 탐침 — Euler 분해 순서

`Orientation(90, 90, 0)` 을 써 넣고 저장한 뒤 **Studio 가 어떻게 되쓰는지 읽는다.**
`(90, 0, −90)` 으로 되쓰면 짐벌락 정규화이고, 이 등가가 성립하는 순서는 6개 중 **ZXY 하나뿐**이다.

순서를 틀리면 pitch/roll 이 0 이 아닌 인스턴스만 조용히 망가진다 —
YXZ 로 분해했을 때 최대 160°, 전체의 24 % 가 10° 초과로 틀어졌다.
순수 yaw 만 있는 인스턴스는 순서와 무관하므로 **나무만 보고 "맞다"고 판단하면 안 된다.**

## 2. 기준자 Part — 단위·배율

엔진 `Part` 는 프리미티브라 `Size` 가 cm 라는 데 이견이 없다.
문제의 MeshPart 와 **같은 자리에 같은 의도 크기로** Part 를 놓고 한 장 찍어 비교한다.

산곡에서 `Size 6500×200×6500` Part 는 65 m 슬래브로 나왔고 같은 자리의 MeshPart 는
안 보였다 → `Size` 가 백분율이 아니라 cm 라는 결론. ([`PLACEMENT_SPEC.md` §5](PLACEMENT_SPEC.md))

## 3. 전부 원점에 놓기 — 피벗 규약

여러 메시를 `(0,0,0)` 에 놓아본다. 한 자리에 겹쳐 쌓이면 **bbox 중심** 규약이다.
월드 좌표가 구워진 메시라면 제자리에 조립된다.

## 4. 허공 프로브 + 축 큐브 — 거울상·180° 회전

의심 메시 사본을 맵 밖 허공(Y=5000)에 띄우고 `+X` 빨강 / `+Z` 파랑 큐브를 세워 한 장 찍는다.
CFrame·노멀·텍스처 값 대조로는 **절대 안 보인다.**
상세는 [`LESSONS_SANGOK2.md` §1](LESSONS_SANGOK2.md).

> 카메라가 `+Z` 를 볼 때 **화면 왼쪽이 `+X`** 다. 스크린샷으로 x 경계를 판단할 때 늘 뒤집힌다.

## 5. 타일 체스판 색칠 — 선이 타일 경계인지 아닌지

지형 타일의 `Color` 를 빨강/파랑 체스판으로 넣으면 경계가 눈에 보인다.
문제의 선이 **그 색 경계와 겹치는지** 한 번에 판정된다.

사람이 화면을 보고 있으면 이걸 띄워 두고 물어보는 게 가장 빠르다 —
실제로 이 방법으로 "이음매 맞다"를 확정하고 기하 가설을 전부 버렸다.
판정이 끝나면 `Color` 를 `255,255,255` 로 되돌린다.

## 6. 구운 텍스처 가장자리 픽셀 읽기 — 텍스처 탓인가 기하 탓인가

타일 PNG 의 **맨 바깥 행/열 픽셀**을 안쪽과 직접 비교한다. 오프라인이고 1초면 끝난다.

산곡 측정: 바깥 `81,78,48` vs 안쪽 `84,80,51` → 사실상 동일.
**베이크 마진 문제가 아니므로 재발행이 필요 없다**는 판단을 여기서 내렸다.

## 7. 블렌더 원본에서 bbox 재계산 — 정렬 오차 정량화

타일별 bbox 중심·크기를 원본 메시에서 다시 계산해 레벨값과 대조한다.

산곡 결과: **최대 오차 0.006 cm (0.06 mm).** 값은 이미 완벽했다.
이걸 재고 나서야 "어긋나서 벌어진 게 아니다"가 확정됐고, 좌표를 더 정밀하게 맞추려는
시도를 그만둘 수 있었다. **고치기 전에 얼마나 틀렸는지부터 재라.**

## 8. 조명 항목 하나씩 끄기

`Lighting` 서비스 속성(`ClockTime`·`AmbientSkyBrightness`·`SunCastShadow`)은
`level.apply` 로 **즉시 반영된다**(MeshPart 속성은 반영 안 됨).

이음선의 남은 12 % 밝기 단차는 이 실험으로 잡았다 —
태양광만 남기면 사라지고 하늘광만 남기면 커진다 → 메시 단위 스카이 오클루전.
기하 가설을 아무리 세워도 안 나왔던 답이다.

## 9. 격리 테스트

원인이 상호작용인지 단독인지 가를 때, 나머지를 `CFrame.Position.Y -= 200000` 으로
잠깐 치우고 둘만 남긴다. 되돌리기는 백업 파일 복사 한 번.

## 10. 마젠타 슬랩

콜리전 슬랩 15장쯤을 `transparency 0, color 255,0,255` 로 켜서 눈높이 한 장.
마젠타가 보이면 윗면이 지형 위다. ([`TERRAIN_COLLISION.md` §5-1](TERRAIN_COLLISION.md))

## 스크린샷에 대해

- **`game.screenshot` 은 지금 사용자가 보고 있는 에디터 뷰포트를 그대로 찍는다.**
  에디터 카메라는 RPC 로 못 움직이므로, 사용자가 문제를 보고 있을 때 바로 받는 게 가장 빠르다.
  (레벨의 `Camera` 인스턴스는 인게임 추적 카메라라 무관하다.)
- 플레이 중에는 플레이어 시점만 나온다. 원하는 위치에서 시작시키려면 다른 `SpawnLocation` 의
  `Enabled` 를 잠깐 `false` 로 두고 끝나면 되돌린다. 스폰이 여러 개면 **랜덤**으로 뽑힌다.
- `level.apply` 직후 스크린샷의 **회색 줄은 선택 아웃라인**이다. LOD 틈이나 이음선으로 오독하지 말 것.
- Studio 로그는 `%LOCALAPPDATA%\Sandbox\Saved\Logs\Sandbox.log`. **타임스탬프는 UTC** 다.
